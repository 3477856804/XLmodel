## 一、结论摘要（先讲答案）

| # | 问题 | 第一性根因 | 性质 | 修复难度 |

## 二、错误清单（源码级缺陷）

### E-01～E-03 Dart 编译错误（`flutter build` 必失败，优先修）

| 编号 | 文件:行号 | 问题 | 后果 |
|---|---|---|---|
| E-01 | `frontend/lib/pages/dashboard_page.dart:387` | `switchModel(m.path)` 直接传 String；生成的 gRPC 客户端方法 `switchModel(SwitchModelRequest)` 遮蔽了 client_ext 的 String 扩展重载 | Windows Release 构建失败 |
| E-02 | `frontend/lib/pages/plugins_page.dart:2414` | `List<String> args;` 非空局部变量在 Linux/macOS/Windows 之外的分支不会赋值，Dart 明确赋值分析报错 | 同上 |
| E-03 | `frontend/lib/pages/settings_page.dart:3964` | 同 E-02（另一处 `_openExternal`） | 同上 |

> 修复模式：E-01 改 `pb.SwitchModelRequest(path: m.path)`；E-02/E-03 改 `List<String>? args;` + `if (bin != null && args != null)` 守卫 + `Process.run(bin!, args!)`。
> 排查中另发现 `frontend/lib/widgets/mcp_panel.dart:18` 的 `List<String> args;`——经核实为类字段且有构造默认值（`this.args = const []`），**非错误**（排除误报）。

### E-04 潜伏打包隐患：`backend.spec` 的 `contents_directory` 传错对象

- `packaging/backend.spec:262` 把 `contents_directory='.'` 传给 **COLLECT**；PyInstaller 6.22.3 实测该参数在 `COLLECT.__init__` 里**被静默忽略**（只从 EXE 实例读取），实际产物仍是 `_internal/` 布局。
- 当前不炸的唯一原因：所有消费方（`config.resource_dir`、`webpanel`、`runtime_hook`、`assemble_windows.py`）都从 `sys._MEIPASS` 动态推导。
- 危险性：spec 注释（201-204 行）与 `docs/PACKAGING.md` 声称「平铺」与事实不符；若有人按文档把参数挪到 EXE() 变成真平铺，`assemble_windows.py` 的 `.star_core` 跳过规则会让插件种子静默失效——**修文档比修参数重要**。
- 处置：删除被忽略的参数 + 注释改为如实描述 `_internal/` 布局（行为零变化，消除误导）。

### E-05 依赖安装的「假性成功」链路（问题 1 的代码侧根因）

- `backend/core/deps.py:87-91`：frozen 下 `_run_install` 第一行短路失败，但该失败只经 `_emit` 写进 `BackgroundTaskManager` 的 `task.output/result`。
- `backend/rpc/server.py:633`：`_bg_start` 同步返回 `ok:true + task_id`，前端 `settings_page.dart:3173-3175` 据此弹「已在后台开始」并刷新——missing 列表原样不动。
- 前端全文**无 `agent:task` 轮询代码**，后台失败结果无人读取 → 用户视角「点击没反应」。
- `settings_page.dart:3662-3667`：frozen 金色横幅说「不能装」，但安装按钮仍可点，且回调 `_installPkg` 从不设置 `_depsInstalling`（与「一键补齐」入口反馈不对称）。

## 四、五大问题：根因 → 可行可验证方案

### 问题 1｜环境依赖点击下载安装，没有反应

**根因链**（按贡献排序）：
1. **frozen 模式 pip 不可用**（硬事实）：`sys.executable` 是 PyInstaller bootloader 而非 CPython 解释器，`-m pip` 不可行；`backend.spec:170` 还显式 excludes 了 `pip`。安装必然失败。
2. **失败不可见**：同步返回 `ok:true + task_id`（「已在后台开始」），后台毫秒级失败，结果只进 `task.output/result`，前端不轮询 `agent:task result`。
3. **UI 自相矛盾**：frozen 横幅说「不能装」，按钮仍可点且回假性成功；`_installPkg` 不进 loading 态（可重复点击）。
4. 次要：全部就绪时返回 `note`，前端仍弹「已在后台开始」。

**修复方案**（本次实施）：
- 后端：`deps.py` 新增 `precheck_install()`（frozen / pip / 网络同步预检，`_run_install` 复用）；`server.py` install 分支在 `_bg_start` 前调用，不过即同步返回带可执行命令的错误。
- 前端：`_installPkg` 增加 frozen 前置拦截与 `_depsInstalling` 状态；安装回执统一处理（`note`/`task_id`/`error` 分别展示）；frozen 时缺失卡片安装按钮置灰。
- 根治建议（后续）：把 light 档依赖（psutil/jieba/requests/aiohttp/edge-tts）在打包时内置，用户根本没有安装诉求；torch 大栈继续排除。

**验证方法**：
```bash
# 源码态：python main.py --install-deps psutil   （应真实安装）
# 打包态：点「安装」→ 应立即看到红条：
#   「打包模式（frozen）无法在线安装依赖…请用源码模式运行 python main.py --install-deps <包名>」
# 不再出现「已在后台开始」的假性成功；按钮在 frozen 下置灰。
```

### 问题 2｜音色切换没有效果

**根因**：`edge-tts==7.2.8` 的 `Sec-MS-GEC` 令牌不再被微软服务端接受（WebSocket 握手 403）。实测对照：同机同网络，7.2.8 → `WSServerHandshakeError: 403`、0 字节音频；7.3.1 → 正常出声（21KB/30  chunks）。已排除：配置键不匹配（`voice.id` 全链路一致，日志显示 voice 随切换变化）、打包缺依赖（edge_tts/aiohttp 全在包内，`--selftest` OK）、时钟漂移（误差 3s）、代理（无）。
时间线：冻结清单 10-11 锁 7.2.8 → 微软 10-13 收紧校验 → 官方 10-13 发布 7.3.0/7.3.1 修复。**「打包后坏」是时间巧合，非打包引入。**

**修复方案**（本次实施）：
- `requirements_frozen_xiaoling_pkg.txt:17`：`edge-tts==7.2.8` → `edge-tts==7.3.1`；`requirements.txt:42`：`edge-tts>=6.1.0` → `>=7.3.1`；重装 venv 后重新打包（纯 Python 包，无 ABI 风险）。
- `server.py` ReadAloud：合成 0 字节时把 `result.error` 写进日志（下次故障从「猜」变「看」）。
- `config.py:530`：validate 校验回落到真实生效的 `voice.id`（原来校验的是没人写的 `tts.edge_voice`）。
- 用户侧即时恢复（不重打包）：edge_tts 为纯 Python 包，可在 `%LOCALAPPDATA%\Xiaoling\app\_internal` 用 7.3.1 目录整体替换旧版，重启生效（临时手段，正式分发仍应重打包）。

**验证方法**：
```bash
# venv 内直接验证（不必等打包）：
pip install edge-tts==7.3.1
python -c "import asyncio,edge_tts; asyncio.run(edge_tts.Communicate('你好','zh-CN-XiaoxiaoNeural').save('/tmp/t.mp3'))" && ls -la /tmp/t.mp3
# 打包后：设置页逐个切换音色试听；backend.log 不再出现 'TTS produced no audio'
```

### 问题 3｜训练配置好可用 API 后，仍无法正常开始训练

**根因链**：
1. **产品预期缺口（主因）**：用户配的「API」与微调启动完全无关——`trainer._prepare()` 只看 torch/transformers/peft 可导入 + HF 格式基座（`trainer.py:528-537`）；而打包版 `backend.spec:158-160` **有意排除** torch 栈（避免 modelscope JIT 编译 CUDA 让构建崩溃）。API 唯一消费者是蒸馏老师端与连通性测试。
2. **A1 代码 bug**：老师端 `teacher_config()` 只读 `deepseek_*` 旧键（`growth.py:1150-1152`），用户在设置页 `api.*` / 训练页 `training.api_*` 配的端点它完全不看 → 「老师端未配置」跳过 → 「配了等于没配」。
3. **A2 半接线**：`api_test` 的 base 走回落链、key/model 只从 `training.api_*` 直读（`trainer.py:1368-1377`）→ 设置页配的需鉴权端点测试必 401。
4. **A3 前端无前置校验**：训练页有 torch/peft 红绿 chip 但不禁用「开始训练」；无 frozen 横幅；错误文案「请 pip install」在打包态是死指令。

**修复方案**（本次实施）：
- `trainer.py:_prepare` 的 ImportError 文案按 `sys.frozen` 分支：打包态改告知「未内置训练栈 + 没有 pip，请用源码模式 `python main.py`」。
- `growth.py:teacher_config` 增加回落链 `deepseek_* → training.api_* → api.*`，任何一处配过都算数，并标明 source。
- `trainer.py` 新增 `_resolve_api_plain()`（同优先级的**明文**解析，仅进程内消费），`api_test` 改用它，消除 401 假象。
- `training_page.dart`：`_startBtn` 增加前置校验（torch/transformers/peft 缺失时点击即展示真实原因，不再走必然失败的启动）；`_envCard` 增加 frozen 横幅（并说明 API 仅用于蒸馏/测试）；`server.py` 的 `training:env` 增加 `frozen` 字段供前端判断。
- 中期建议：提供「训练完整版」打包档位（单独 spec 不排除 torch 栈），或 UI 明示唯一出路命令。

**验证方法**：
```bash

#   「当前为打包版，未内置 PyTorch 训练栈（缺少：torch、transformers、peft）…请使用源码模式」
# 而不是转圈几秒后看到「请 pip install」（打包态没有 pip）。
```

### 问题 4｜3D 形象未能正常加载（是否为环境依赖未安装？）

**结论**：**部分是**。经实测排除的项：viewer.html/vendor JS/VRM 文件全部存在且 HTTP 200；VRM 文件完整（glTF magic、长度、179 节点）；后端 3D 链路零第三方依赖（纯标准库 `http.server`）；端口三方对齐（launcher→`--web-port`→`XIAOLING_WEB_PORT`→pin）本副本已修。真正的根因：

| 优先级 | 根因 | 性质 |
|---|---|---|
| P0 | **WebView2 Runtime 缺失或过旧**：桌面真 3D 全靠 `InAppWebView`（Windows=WebView2），viewer.html 用 importmap+ES module 需要较新 Chromium 内核；环境创建失败往往不同步抛错 → 空白页 → 12s 看门狗误判「服务未响应」 | **真环境依赖（但不是 Python 依赖）** |
| P1 | **启动竞态**：`viewer_port.dart:171-174` pin 端口 6 轮不通、后端 gRPC 也没就绪时，仍把**过期 pin 当结果返回** → WebView 拼出连不上的 URL → `onLoadError` 直接落错误态，**无自动重试**，冷启动慢的机器必现 | 时序 bug |
| P2 | GPU/WebGL 不可用（无显卡/远程桌面/驱动异常）→ `ViewerFail.render`，但文案说「文件可能损坏」，张冠李戴 | 真缺依赖（GPU 层） |
| P3 | `webpanel.py:656` `ThreadingHTTPServer` 默认 `allow_reuse_address=1`（Windows SO_REUSEADDR 可抢占已占用端口）→「假启动」：日志打印已监听实际不通 | 端口探测半修（launcher 侧已修，后端侧残留） |

**修复方案**（本次实施）：
- `viewer_port.dart`：pin 不通且问不到后端时**返回 0**（诚实「服务未启动」），不再返回过期 pin。
- `model_showcase.dart`：`_resolveViewerPort` 收到 0 时先**自动重试 4 轮**（1s/2s/2s/2s 退避）再落错误态；`_retry()` 重置重试计数；`onLoadHttpError` 404 文案改为「查看器资源缺失」；service 类提示补充「多次重试无效请安装/更新 WebView2 Runtime」。
- `webpanel.py:_make_server`：bind 前显式 `SO_EXCLUSIVEADDRUSE` 探测（Windows 独占语义），杜绝假绑定。
- `backend.spec`：删除被 COLLECT 忽略的 `contents_directory='.'` 并修正误导性注释（见 E-04）。

**验证方法**：
```bash

# 2) 后端链路自证：backend.exe --no-web --web-port 8792，

```

### 问题 5｜多平台连接没有反应，没有弹出认证或连接

**根因链**：
